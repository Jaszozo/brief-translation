# Brief 转译

把“客户给来的需求”，整理成“策划可以开始工作的 Brief”。

面向 Account、Planner、Creative 和品牌方。适合需求零散、只有 KPI、方向尚未确定，或多份材料口径不一致的项目。

## 它能帮你做什么

- 抓住项目最想实现的结果，不把发内容、做活动当成最终目的。
- 梳理汇报对象、决策者及其偏好，不按职位猜测诉求。
- 分清需要使用者确认的选择，以及应由策划研究的问题。
- 提出有线索支持的深层需求假设，说明若成立会怎样影响方案，再请使用者确认。
- 明确交付内容和深度，不自动扩写完整策略或执行方案。

## 你会得到什么

通常是一份 300–600 字的工作 Brief，简单任务更短：

| 部分 | 回答的问题 |
| --- | --- |
| 道：目标与顾虑 | 最想得到什么，最担心什么？ |
| 深度洞察（假设） | 是否还有深层需求？若成立，方案应侧重哪里？ |
| 法：策划任务 | 为实现目标，应先研究或解决什么？ |
| 术：交付要求 | 具体交什么，做到多深？ |
| 需要确认的点 | 哪些答案会真正改变工作？ |

原始 Brief 决定主线，假设不能替代事实。

## 如何使用

### 使用支持本地 Skill 的 AI 工具

从仓库页面选择 **Code → Download ZIP**，解压后保留 `SKILL.md` 与 `references/` 的相对位置。按所用工具的本地 Skill 导入方式，导入整个文件夹；调用名称为 `brief-translation`。

### 不使用 Skill 导入功能

将 [SKILL.md](SKILL.md) 和 [方法依据](references/methods.md) 提供给支持文件阅读的 AI，再提供项目材料，并发送：

> 请按这份 Brief 转译指令处理以下项目资料。直接输出转译结果，不写推理过程；将未确认的判断标为假设，并列出需要我确认的点。

可提供：原始需求、品牌或产品资料、指标、预算、时间、沟通补充，以及汇报对象的偏好。有什么先给什么，不必先填完整表格。

AI 是否能读取附件、联网核查趋势，取决于所用工具及权限；不能读取时应明确说明，而不是编造内容。

## 一个虚构示例

**输入**

> 我们设计了一个新角色，想推广，但还没确定它应该承担什么任务。先要方向建议。

**输出节选（示意）**

- **道：** 先明确角色的用途：帮助记住品牌、促进用户互动，还是发展独立内容资产？
- **深度洞察（假设）：** 角色已设计、用途未定，可能需要先解决角色与品牌的关系。若成立，优先判断它应在哪些场景发挥作用，而不是先选传播形式。
- **法：** 比较不同用途与品牌、受众及运营资源的适配程度。
- **术：** 角色用途建议与后续推广方向，以规划为主。
- **需要确认：** 上述假设是否符合实际？当初设计角色希望解决什么？哪些设定可以调整？

示例不含真实客户信息，不代表实际项目结论或固定输出。

## 方法与边界

借鉴双钻模型的问题定义、战略取舍及 SMART 目标检查，用“道法术”组织输出。具体来源和适用边界见 [方法依据](references/methods.md)。这是工作方法的组合，不是任何机构的认证模型。

它不是完整传播策划工具，也不保证客户认可或业务效果。当前趋势需要核实；合理假设仍需确认。对明确的小任务，不强加品牌战略或宏观分析。
